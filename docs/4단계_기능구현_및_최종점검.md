## 4-1. 공모 안내 · 응모 폼 화면

| 항목 | 결과 |
|---|---|
| `/` 공모 안내 | 주제·자격·일정·시상·심사기준·유의사항 렌더링 확인 |
| `/apply` 응모 폼 | 7개 입력(팀명·구성원·제목·요약·기대효과·전화·메일) + 동의 체크 + 제출 |
| 고정 고지 | "AI 평점·심사평은 검토 초안, 최종 심사는 사람" 화면 표시 |
| 검증 | 배포 주소에서 두 화면 렌더링 확인(브라우저) |

## 4-2. Airtable 저장 (`POST /api/apply`)

- 서버에서 입력 검증 → Airtable `Applications`에 레코드 생성, `SubmittedAt` 자동 기록.
- 검증: 가상 1건 저장 후 11개 필드 확인, 테스트 레코드 삭제.

## 4-3. AI 검토 (Gemini)

- `POST /api/apply`가 Gemini로 **분야·평점(1~5 정수)·근거·심사평 초안**을 생성해 같은 레코드에 저장.
- 개인정보(팀명·구성원·연락처)는 Gemini에 전송하지 않음(제목·요약·기대효과만).
- 실패 시 응모는 정상 저장되고 AI 칸만 비움(자동 재시도 없음).
- 모델: `gemini-3.5-flash` (3.8-flash는 30초+ 지연으로 제외 — `docs/3단계_환경세팅_결과.md` 참고).
- 검증: `reviewed: true`, 응답 ~2.5초, Airtable에 `AICategory`·`AIScore`·`AIScoreReason`·`AIReviewDraft` 저장 확인.

## 4-4. 접수 현황 (`GET /api/status`, `/status`)

- 화면을 열 때 **자동 호출하지 않음**. **새로고침 버튼을 눌렀을 때만** `/api/status` 호출.
- 분야별 건수·비율만 표시(이름·연락처 미표시).
- 검증: `/status`에서 자동 호출 없음 확인, 새로고침 시 분야별 건수 표시.
