## 2. 안내 문구 (홈 페이지 카피)

### 2-1. 히어로

- **제목**: AI로, 우리 주변의 불편을 바꿉니다
- **부제**: 캠퍼스와 부산 지역의 문제를 AI로 푸는 아이디어를 찾습니다. 당신의 아이디어가 1차 검토를 거쳐 심사위원에게 닿습니다.
- **버튼**: `응모하러 가기` (→ `/apply`) · `접수 현황 보기` (→ `/status`)
- **배지**: 접수 기간 2026-11-03 ~ 11-30 · 총상금 200만원

### 2-2. 무엇을 모집하나요

> 제품, 서비스, 정책, 자동화 도구 무엇이든 좋습니다. 아직 만들지 않아도 됩니다. **"누구의 어떤 불편을, AI로 어떻게 푸는가"** 가 분명하면 됩니다.

### 2-3. 응모 자격

> 재학생·휴학생이면 누구나. 개인 또는 팀(인원 제한 없음).

### 2-4. 일정 (타임라인)

| 단계 | 기간 |
|---|---|
| 접수 | 2026-11-03 ~ 11-30 (4주) |
| 1차 검토 (AI 초안) | 접수 즉시 자동 |
| 사람 심사 | 2026-12-01 ~ 12-07 |
| 발표 | 2026-12-11 |

### 2-5. 시상

> 대상 1팀 80만원 · 최우수 2팀 각 40만원 · 우수 3팀 각 20만원 · 장려 다수 기념품 (총 200만원)

### 2-6. 심사 기준 (요약 카드 3개)

| 축 | 묻는 것 |
|---|---|
| **창의성** | 기존에 없던 접근인가, 문제를 새롭게 정의했는가 |
| **실현가능성** | 지금 있는 도구·데이터·예산으로 실제 만들 수 있는가 |
| **기대효과** | 해결되면 누가 얼마나 좋아지는가, 파급 범위는 |

### 2-7. 유의사항 (홈 하단 고정)

- AI가 붙이는 분야·평점·심사평은 **검토 초안**이며, **최종 심사는 사람이** 합니다.
- 응모자의 이름·연락처는 **공개 화면(접수 현황)에 표시되지 않습니다.**
- 접수 현황에는 **분야별 건수만** 공개됩니다.

## 3. 응모 폼 문구 (/apply)

### 3-1. 필드 라벨·플레이스홀더

| 항목 | 라벨 | 플레이스홀더 | 도움말 |
|---|---|---|---|
| 팀명 | 팀명 | 예: 캠퍼스클린 | 필수 |
| 구성원 | 구성원 (이름만) | 예: 김철수, 이영희 | 공개 화면에 표시되지 않습니다 |
| 아이디어 제목 | 아이디어 제목 | 한 줄로 요약해 주세요 | 필수 |
| 아이디어 요약 | 아이디어 요약 | 어떤 불편을, AI로 어떻게 푸는지 30자 이상 | **AI 검토의 주 재료**입니다 |
| 기대 효과 | 기대 효과 | 누가 얼마나 좋아지는지 | 필수 |
| 전화번호 | 연락처 (전화) | 010-0000-0000 | 비공개, 회신용 |
| 메일 주소 | 연락처 (메일) | you@example.com | 비공개, 회신용 |

### 3-2. 동의 문구 (체크박스 1개)

> [필수] 개인정보(연락처)는 회신 목적으로만 사용하며 공개 화면에 표시하지 않는 것에 동의합니다.

### 3-3. 제출 문구

- 버튼: `응모 제출`
- 제출 중: `검토 중…` (AI 검토가 붙는 동안)
- 성공 메시지: `접수되었습니다. AI 1차 검토 초안이 함께 저장되었습니다. (AI 초안 · 최종 심사는 사람)` 
- 실패 메시지: `접수에 실패했습니다. 잠시 후 다시 시도해 주세요.` (자동 재시도 안 함, 사용자가 직접 다시 누름)

### 3-4. 폼 하단 고정 고지

> 제출하면 AI가 분야·평점·심사평 **초안**을 생성합니다. 이는 참고용이며 **최종 심사는 사람이** 합니다.

## 4. 접수 현황 문구 (/status)

- **제목**: 접수 현황
- **부제**: 분야별 접수 건수 (이름·연락처는 공개하지 않습니다)
- **버튼**: `새로고침` — **이 버튼을 눌렀을 때만** 데이터를 불러옵니다. 화면을 열 때 자동 조회하지 않습니다.
- **빈 상태**: `아직 접수된 응모가 없습니다. 새로고침을 눌러 확인하세요.`
- **총계 표시**: `총 N건`
- **하단 고정 고지**: `AI 평점·심사평은 검토 초안이며, 최종 심사는 사람이 합니다.`

## 5. 분야 선택지 — 확정 (5개)

AI는 이 중 **정확히 하나**를 고른다. 코드는 Airtable single select 값·Gemini 출력과 **글자까지 동일**하게 쓴다.

| 영문 코드 | Airtable 옵션 / 화면 표시 | 설명 (AI 판단 기준) | 예시 |
|---|---|---|---|
| `learning` | 학습·교육 | 강의·과제·학습 지원, 교육 접근성 | 강의 요약 봇, 맞춤 학습 추천 |
| `campus` | 캠퍼스생활 | 시설·행정·교통·식당 등 교내 편의 | 빈 강의실 안내, 셔틀 최적화 |
| `community` | 지역·커뮤니티 | 부산 지역 문제, 주민·상권·복지 | 소상공인 매칭, 민원 분류 |
| `green` | 환경·지속가능 | 에너지·폐기물·기후, ESG | 분리수거 안내, 에너지 절감 |
| `etc` | 기타·융합 | 위에 안 맞거나 여러 분야 융합 | 두 분야 이상 결합 |

> 애매하면 **가장 가까운 하나**를 고른다. `etc`는 최후의 선택이고, 끝까지 하나만 고른다.

## 6. 심사 기준 상세 (레벨 디스크립터)

AI 프롬프트에 그대로 넣어 평점 근거를 일관되게 만든다. AI는 3축을 종합해 **1~5 정수** 하나를 낸다.

| 점수 | 창의성 | 실현가능성 | 기대효과 |
|---|---|---|---|
| **5** | 기존에 없던 관점, 문제 재정의 | 현 도구로 바로 시제품 가능 | 매우 넓고 명확한 파급 |
| **4** | 참신한 변형·조합 | 계획이 구체적, 일부 자원 필요 | 특정 집단에 뚜렷한 개선 |
| **3** | 흔한 아이디어에 개선 | 개념은 타당, 실행은 미정 | 개선은 있으나 범위 제한 |
| **2** | 기존 것을 거의 그대로 | 실행 계획이 모호 | 효과가 불분명 |
| **1** | 독창성 없음/주제 벗어남 | 실현 근거 없음 | 효과 기대 어려움 |

평점은 3축의 **종합 인상**으로 하나만 낸다. 근거 한 줄에는 어느 축이 강점/약점인지 드러나게 쓴다.

## 7. AI 검토 지시문 — 최종본

> 서버 코드(`api/_lib/gemini.ts`)에 문자열 상수로 넣는다. `{...}`는 서버가 채운다.

### 7-1. System Instruction (그대로 복사)

```text
너는 아이디어 공모전의 1차 검토를 돕는 심사 보조원이다.
주어지는 "아이디어 제목 / 아이디어 요약 / 기대 효과"만 읽고 다음 세 가지를 만든다.
너의 결과는 최종 심사가 아니라 사람이 볼 "검토 초안"이다.

[분야] 아래 5개 중 정확히 하나만 고른다. 반드시 주어진 영문 코드로만 답한다.
  - learning  : 학습·교육 (강의·과제·학습 지원, 교육 접근성)
  - campus    : 캠퍼스생활 (시설·행정·교통·식당 등 교내 편의)
  - community : 지역·커뮤니티 (지역 문제, 주민·상권·복지)
  - green     : 환경·지속가능 (에너지·폐기물·기후, ESG)
  - etc       : 기타·융합 (위에 안 맞거나 여러 분야 융합)
  애매하면 가장 가까운 하나를 고르고, 끝까지 하나만 고른다.

[평점] 1~5 사이의 "정수"만 낸다. 0이나 소수점은 쓰지 않는다.
  심사 축은 (1) 창의성 (2) 실현가능성 (3) 기대효과이며, 세 축을 종합해 하나의 점수를 낸다.
  기준: 5=매우 우수, 4=우수, 3=보통, 2=미흡, 1=매우 미흡.
  같은 답에 "그렇게 본 근거"를 한국어 한 줄(60자 이내)로 함께 낸다.
  근거에는 어느 축이 강점/약점인지 드러나게 쓴다.

[심사평 초안] 한국어로, 강점 2가지와 보완할 점 2가지를 담아 "다섯 문장 이내"로 쓴다.
  - 사실을 지어내지 않는다. 주어진 내용에 근거해서만 쓴다.
  - 최종 심사가 사람임을 전제로, 단정하지 말고 제안하는 어조로 쓴다.

[출력 형식] 설명·인사말·코드블록 없이 아래 JSON 객체 하나만 출력한다.
{"category":"<learning|campus|community|green|etc>","score":<1~5 정수>,"score_reason":"<한 줄 근거>","review":"<강점2·보완2, 5문장 이내 심사평 초안>"}
```

### 7-2. User Content 템플릿 (서버가 채움)

```text
[아이디어 제목]
{IdeaTitle}

[아이디어 요약]
{IdeaSummary}

[기대 효과]
{ExpectedImpact}
```

> 개인정보(팀명·구성원·전화·메일)는 **Gemini에 보내지 않는다.** 위 3개만 전달.

### 7-3. 출력 JSON 스키마 (서버가 강제)

```json
{
  "category": "learning | campus | community | green | etc",
  "score": 1,
  "score_reason": "string (<= 60자)",
  "review": "string (<= 5문장)"
}
```

### 7-4. 서버 검증 규칙 (자동 재시도 없음)

| 조건 | 처리 |
|---|---|
| 응답이 유효 JSON | 그대로 사용 |
| JSON 파싱 실패 | AI 칸 전부 비움, **본문은 정상 저장**, 오류 로그 |
| `category`가 5개 코드 밖 | AI 칸 비움, 오류 로그 (**재분류 요청 안 함**) |
| `score`가 정수 아님 or 1~5 밖 | `AIScore`만 비움(`0` 절대 저장 안 함), 나머지는 저장 |
| `review`가 5문장 초과 | 서버에서 문장 단위로 잘라 저장 (또는 그대로 저장 후 로그) |
| Gemini 타임아웃/오류 | **1회 시도 후 중단**, AI 칸 비운 채 저장 |

## 8. 예시 입출력 (테스트용 · 가상 응모)

**입력**
```text
[아이디어 제목] 빈 강의실 실시간 안내 봇
[아이디어 요약] 학생이 비어 있는 강의실을 실시간으로 찾아 공부할 수 있게 하는 챗봇. 시간표·출입 데이터를 AI가 분석해 빈 좌석을 추천한다.
[기대 효과] 공부할 곳을 못 찾는 시간을 줄이고, 유휴 강의실 활용률을 높인다.
```

**기대 출력**
```json
{
  "category": "campus",
  "score": 4,
  "score_reason": "실현가능성과 기대효과가 높으나 독창성은 보통 수준",
  "review": "시간표와 출입 데이터를 결합한 점이 실현가능성을 높입니다. 유휴 강의실 문제를 정면으로 다뤄 효과가 뚜렷합니다. 다만 유사한 빈자리 안내 서비스가 이미 있어 차별화가 필요합니다. 개인정보·출입 데이터 활용의 동의 절차를 구체화하면 완성도가 올라갑니다."
}
```
