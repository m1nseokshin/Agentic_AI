## 0. 한 줄 정의

응모를 받아 **Gemini가 1차 검토 초안(분야·평점·심사평)** 을 붙이고, 그 결과를 **Airtable에 한 줄로 쌓는** 웹사이트.
열쇠(API 키)는 **서버 쪽에만** 두고, 화면 코드에는 넣지 않는다.

```
[GitHub] → [Vercel 배포]
              ├─ 화면: / (안내) · /apply (응모) · /status (현황)
              └─ 서버(api/): ① Gemini 검토  ② Airtable 저장
                                   ↓
                             [Airtable] 응모 + AI 검토 적재
                                   ↓ (다음 단계) GAS 메일
```

## 1. 공모 요강 (확정)

| 항목 | 내용 |
|---|---|
| **주제** | AI를 활용한 캠퍼스·지역 문제 해결 아이디어 |
| **모집 대상** | AI/에이전트로 캠퍼스나 지역의 불편을 푸는 아이디어 (제품·서비스·정책·자동화 모두 가능) |
| **응모 자격** | 재학생·휴학생 (개인 또는 팀) |
| **일정** | 접수 4주 (예: 2026-11-03 ~ 2026-11-30), 심사 1주, 발표 1주 |
| **시상** | 총상금 200만원 — 대상 1팀(80만) · 최우수 2팀(각 40만) · 우수 3팀(각 20만) · 장려 다수(기념품) |
| **심사 기준** | **창의성 · 실현가능성 · 기대효과** 3축으로 1~5점 |

### 분야(카테고리) 선택지 — 5개 고정

AI가 아래 **5개 중 정확히 하나**만 고르게 한다. (자유 서술로 두면 표에서 세어지지 않음)

| 코드 | 표시 이름 | 설명 |
|---|---|---|
| `learning` | 학습·교육 | 강의·과제·학습 지원, 교육 접근성 |
| `campus` | 캠퍼스생활 | 시설·행정·교통·식당 등 교내 편의 |
| `community` | 지역·커뮤니티 | 부산 지역 문제, 주민·상권·복지 |
| `green` | 환경·지속가능 | 에너지·폐기물·기후, ESG |
| `etc` | 기타·융합 | 위에 안 맞거나 여러 분야 융합 |

### 심사 기준 상세

| 축 | 무엇을 보는가 |
|---|---|
| 창의성 | 기존에 없던 접근인가, 문제를 새롭게 정의했는가 |
| 실현가능성 | 지금 있는 도구·데이터·예산으로 실제 만들 수 있는가 |
| 기대효과 | 해결되면 누가 얼마나 좋아지는가, 파급 범위 |

## 2. 페이지 구성 (3페이지 기본)

| 경로 | 이름 | 내용 | 데이터 호출 |
|---|---|---|---|
| `/` | 공모 안내 | 주제·응모 자격·일정·시상·심사 기준, 응모 폼 링크 | 없음 |
| `/apply` | 응모 폼 | 접수 항목 입력 + 제출 → 서버가 검토·저장 | 제출 시 `POST /api/apply` |
| `/status` | 접수 현황 | 분야별 건수 (막대/카드) | **새로고침 버튼 누를 때만** `GET /api/status` |

- 여유가 있으면 글만 있는 페이지 추가: `/criteria`(심사 기준 상세), `/faq`. **데이터를 읽어 그리는 화면은 `/status` 하나뿐**으로 유지.
- 모든 화면 하단 고정 문구: **"AI 평점·심사평은 검토 초안이며, 최종 심사는 사람이 합니다."**
- `/status`에는 **분야별 건수만** 표시. 팀명 외 이름·연락처는 **절대 노출하지 않음**.

## 4. Airtable 필드 구조

> **필드 이름은 영문(API Name)으로 둔다.** 한글 필드명 인코딩 깨짐(§Ⅵ)을 피하기 위함. 화면 표시는 한글.
> 테이블 이름도 영문 예: `Applications`.

| # | 필드 이름(영문) | 표시(한글) | 필드 타입 | 채우는 주체 | 메모 |
|---|---|---|---|---|---|
| 1 | `TeamName` | 팀명 | Single line text | 응모자 | |
| 2 | `Members` | 구성원 | Single line text | 응모자 | |
| 3 | `IdeaTitle` | 아이디어 제목 | Single line text | 응모자 | |
| 4 | `IdeaSummary` | 아이디어 요약 | Long text | 응모자 | AI 주 재료 |
| 5 | `ExpectedImpact` | 기대 효과 | Long text | 응모자 | |
| 6 | `Phone` | 전화번호 | Phone number | 응모자 | 비공개 |
| 7 | `Email` | 메일 주소 | Email | 응모자 | 비공개, 다음 단계 회신용 |
| 8 | `SubmittedAt` | 접수일시 | Date (include time) | 자동 | 서버가 ISO 저장 |
| 9 | `AICategory` | AI 분야 | Single select (5개 옵션) | Gemini | 옵션=분야 5개 |
| 10 | `AIScore` | AI 평점 | **Number (integer, precision 0)** | Gemini | **1~5만. 0·소수 입력 시 저장 실패** |
| 11 | `AIScoreReason` | AI 평점 근거 | Single line text | Gemini | 한 줄 |
| 12 | `AIReviewDraft` | AI 심사평 초안 | Long text | Gemini | 강점2·보완2, 5문장 이내 |
| 13 | `JudgeScore` | 담당자 확정 평점 | Number (integer, precision 0) | **사람** | **AI 평점과 별도 칸** ★ |
| 14 | `MailSentAt` | 발송일시 | Date (include time) | 다음 단계(GAS) | 이미 보낸 건 재발송 방지 |

**핵심**: ⑩ `AIScore`와 ⑬ `JudgeScore`를 **다른 칸**으로 둔다. 칸이 두 개라는 사실만으로 "AI가 낸 건 초안"이라는 성격이 남는다.

- `AICategory` single select 옵션 5개: `학습·교육` / `캠퍼스생활` / `지역·커뮤니티` / `환경·지속가능` / `기타·융합`.
- `AIScore`·`JudgeScore`는 **Number(0 정밀도, 1~5)** 또는 Rating(1~5). Rating이면 저장값도 1~5 정수.
- 토큰 권한: `data.records:read`, `data.records:write`, `schema.bases:read` 포함. **대상 베이스를 토큰에 반드시 포함**.

## 5. AI 평가 지시문 (Gemini 프롬프트 초안)

### 입력 → 출력 계약

- 입력: 응모 7항목 중 **팀명·구성원·연락처는 보내지 않는다**. **아이디어 제목·요약·기대 효과만** Gemini에 전달(개인정보 최소화).
- 출력: **아래 키만 가진 엄격한 JSON**. 코드블록·설명 문장 없이 JSON만 반환하도록 지시.

```json
{
  "category": "learning | campus | community | green | etc 중 하나",
  "score": 1,
  "score_reason": "한 줄 근거",
  "review": "강점 2개와 보완 2개를 담은 5문장 이내 심사평 초안"
}
```

### 시스템 지시문 (초안)

```text
너는 아이디어 공모전의 1차 검토를 돕는 심사 보조원이다.
아래 응모작의 "아이디어 제목 / 아이디어 요약 / 기대 효과"를 읽고 세 가지를 만든다.
너의 결과는 최종 심사가 아니라 사람이 볼 "검토 초안"이다.

[분야] 아래 5개 중 정확히 하나만 고른다. 반드시 주어진 영문 코드로만 답한다.
  - learning  : 학습·교육
  - campus    : 캠퍼스생활
  - community : 지역·커뮤니티
  - green     : 환경·지속가능
  - etc       : 기타·융합
  (애매하면 가장 가까운 하나를 고르고, 끝까지 하나만 고른다.)

[평점] 1~5 사이의 "정수"만 낸다. 0이나 소수점은 쓰지 않는다.
  심사 축은 (1) 창의성 (2) 실현가능성 (3) 기대효과 이다.
  1=매우 미흡, 3=보통, 5=매우 우수.
  같은 답에 "그렇게 본 근거"를 한국어 한 줄(60자 이내)로 함께 낸다.

[심사평 초안] 한국어로, 강점 2가지와 보완할 점 2가지를 담아 "다섯 문장 이내"로 쓴다.
  - 사실을 지어내지 않는다. 주어진 내용에 근거해서만 쓴다.
  - 최종 심사가 사람임을 전제로, 단정하지 말고 제안하는 어조로 쓴다.

[출력 형식] 설명·인사말·코드블록 없이 아래 JSON 객체 하나만 출력한다.
{
  "category": "<learning|campus|community|green|etc>",
  "score": <1~5 정수>,
  "score_reason": "<한 줄 근거>",
  "review": "<강점2·보완2, 5문장 이내 심사평 초안>"
}
```

### 사용자 입력 템플릿 (서버가 채움)

```text
[아이디어 제목]
{IdeaTitle}

[아이디어 요약]
{IdeaSummary}

[기대 효과]
{ExpectedImpact}
```

### 서버 측 검증(코드에서 강제)

- `category` ∈ 5개 코드가 아니면 → 재분류 대신 **저장 중단**으로 처리(자동 재시도 금지). 관리자 로그에 남김.
- `score`가 정수가 아니거나 1~5 밖이면 → **해당 응모의 AI 칸 비움**으로 저장하고 기록. (0 저장 시 실패하므로 절대 0을 넣지 않음)
- 응답이 JSON 파싱 실패 → AI 칸 비우고 본문은 정상 저장(응모 자체는 잃지 않음).
- Gemini 호출은 **타임아웃 1회**, **자동 재시도 없음**.

## 6. 기능 단위 (함수/모듈)

### 서버 (`api/`, Vercel Serverless Functions · Node)

| 단위 | 라우트 | 하는 일 | 실패 시 |
|---|---|---|---|
| `validateApplication` | (lib) | 7항목 필수·형식 검증 | 400 반환, 호출 안 함 |
| `reviewWithGemini` | (lib) | 프롬프트 조립 → Gemini 호출 → JSON 파싱·검증 | 1회 타임아웃 후 AI칸 빈 채로 진행 |
| `saveToAirtable` | (lib) | 레코드 생성(영문 필드명 매핑) | 502 반환, **재시도 없음** |
| `POST /api/apply` | `api/apply.ts` | 검증→Gemini→Airtable→결과 반환 | 각 단계 오류 그대로 전달 |
| `GET /api/status` | `api/status.ts` | 레코드 조회→분야별 건수 집계만 반환(개인정보 제외) | 502 반환 |

- 키는 `process.env`에서만 읽음. `VITE_` 접두사 **금지**(접두사가 붙으면 화면 번들에 노출됨).
- 응답에 절대 `Phone`·`Email`·`Members`를 담지 않음.

### 화면 (`src/`, React + Tailwind + shadcn/ui)

| 단위 | 위치 | 하는 일 |
|---|---|---|
| `Layout` | `src/components/Layout.tsx` | 헤더/푸터, 고정 안내 문구 |
| `HomePage` | `src/pages/Home.tsx` | 공모 안내(`/`) |
| `ApplyForm` | `src/pages/Apply.tsx` | 입력·검증·제출·성공/실패 표시 |
| `StatusPage` | `src/pages/Status.tsx` | **새로고침 버튼** → `GET /api/status` |
| `CategoryChart` | `src/components/CategoryChart.tsx` | 분야별 건수 표시 |
| `AiDraftNotice` | `src/components/AiDraftNotice.tsx` | "AI 초안, 최종 심사는 사람" 문구 |

- 라우팅: `react-router-dom`. 폼: `react-hook-form` + `zod`(또는 수동 검증). shadcn/ui: Button, Input, Textarea, Card, Select, Checkbox, Alert, Progress.
- `/status`는 **마운트 시 자동 호출하지 않는다.** `useEffect`로 fetch 금지, 버튼 핸들러에서만 호출.

## 8. 진행 단계와 완료 기준 (한 번에 한 단계)

| 단계 | 하는 일 | 끝났다는 기준 |
|---|---|---|
| **1. 작업 기획** | 이 문서 작성 | 기획서 md 파일이 생겼고 읽어 봤다 ✅ |
| **2. 컨셉·프롬프트 확정** | 안내 문구·분야 5개·심사 기준·AI 지시문 확정 | §1·§5가 확정됐다 |
| **3. 환경 세팅** | GitHub 저장소 → Vercel 연결(빈 화면 배포) → Airtable 베이스·필드 → Gemini 키 → 환경변수 양쪽 등록 | **내 주소로 빈 화면이라도 접속된다** |

| **4-3. AI 검토** | Gemini 붙여 분야·평점·근거·심사평 저장 | 그 줄에 AI 칸이 함께 채워짐, 평점이 1~5 정수 |

## 9. 지켜야 할 네 가지 + 함정 회피

1. **키는 화면 코드에 넣지 않는다** — 서버(`api/`)에서만. `VITE_` 접두사 금지.
2. **가상 응모작으로 테스트** — 실명·실제 개인정보·내부 자료 금지, 메일도 본인/동료 것만.
3. **평점은 초안** — "최종 심사는 사람" 문구를 화면에 고정 표시.
4. **이름·연락처 공개 화면 미표시** — `/status`는 건수만.

함정 회피(§Ⅵ 대응):
- [x] 목록은 **새로고침 버튼 눌렀을 때만** 조회
- [x] 실패해도 **자동 재시도 안 함** (호출 한도 초과 방지)
- [x] 평점은 **1~5 정수만** (0 저장 실패 회피)
- [x] Airtable 필드명 **영문** (한글 인코딩 깨짐 회피)
- [x] 환경변수 **내 컴퓨터 + Vercel 양쪽** 등록
- [x] 코드가 부르는 필드명과 표의 필드명 **글자까지 일치**
